# MaixCAM2 OS04A10 高速采集

目标为 640×360、每秒 360 个真实采集帧。OS04A10 是图像传感器型号；更换光学镜头本身不会增加读出帧率。将 360fps 视为待验证的研发目标，不承诺芯片、具体模组或当前固件已经支持。

## 使用方式

- 用户明确要求猜测未知降采样位、反向试写验证时，使用同级 [os04a10-subsampling-reverse](../os04a10-subsampling-reverse/SKILL.md) 的受控假设实验流程；下文针对已知时序路线的限制不作为拒绝该类已授权实验的理由。只要求计划/创建skill时仍不自动试写。
- 用户要求规划时，完成证据核对、软件分层、开发计划和验收设计；设备检查限于只读，不启动试写寄存器或部署实验驱动。
- 用户要求开发时，沿已完成阶段继续，建立独立采集样例。产物限于相机驱动、采集和测试，不自动扩展到下游业务。
- 不把另一场对话当作已经读取的资料。先查项目记录；缺失的信息明确标为用户陈述、暂定或未核验。

开始时读 [references/baseline.md](references/baseline.md)。它记录本项目已核验的源码入口、版本和证据边界；路径是定位线索，需按当前环境确认。

## 开发流程

1. **建立基线。** 核验主机、板端系统、MaixPy/CDK、MSP、工具链、实际加载库和传感器身份。识别结果须区分 I²C 地址推断与 chip ID 读回。先复现现有 OS04A10 默认模式，保存图像、硬件时间戳和错误计数。
2. **论证模式。** 读 [references/development.md](references/development.md)，取得适用模组的时序资料或可追溯模式表，确认 ROI/binning/subsampling、XCLK、PLL、HTS/VTS、曝光、RAW 位深、MIPI 和 VIN/ISP 限制。输出可行、条件可行、资料不足或有证据不支持的结论。
3. **准备独立实验。** 在用户可写的独立源码副本中固定版本，保存基线哈希。先实现只采集 RAW 的最小 C/C++ 程序；提供有界缓冲、帧元数据、错误统计和正确释放。NV21 为后续单独验证阶段。
4. **适配完整链路。** 依次完成 sensor mode/AE 回调、MIPI/VIN/ISP/内存池、MaixCDK 模式选择和 API 的一致性。已知模式路线只为有时序依据的模式生成寄存器修改；OS04D10 代码不能当作OS04A10已知配置。明确授权的未知采样位研究走上述假设实验流程，类比仅用于提出可证伪的候选。
5. **逐级上板。** 在开发授权范围内，使用独立目录和进程级库路径加载实验版本；验证库实际加载位置。先恢复基线，再按有依据的 120→180→240→360fps 档位推进，不强制创造未受支持的中间档。
6. **验收并交付。** 读 [references/validation.md](references/validation.md)，分开报告 sensor/RAW、NV21、应用消费和显示/编码帧率。交付源码补丁、构建记录、模式说明、采集程序、原始测量记录、报告及已验证回退步骤。

## 必须保持的判断

- 软件 resize/crop、曝光倒数、循环计数、编码文件的 fps 标签都不能证明传感器达到 360fps。
- 不能依据同系列传感器、HDR 多次曝光数量、数组名或总像素吞吐量直接推出可用模式。缺少模式资料且用户未要求假设试验时，继续完成源码分析、测量工具和资料缺口清单，暂停依赖未知时序的硬件写入。用户明确要求猜测验证时，按上述假设实验流程推进，未知语义本身不是重复索要许可或停止全部研发的理由。
- 不直接编辑共享 SDK 的下载缓存作为唯一源码；它可能被重新下载覆盖。不要把 SG200x 的 sensor ABI 用作 MaixCAM2 的 Axera ABI。
- 在有效授权内执行常规构建和可恢复的实验，不重复索要许可。若下一步涉及尚未授权的系统库覆盖、启动配置更改或刷写，先准备可审阅的具体变更、备份与恢复步骤，再请求该项操作的许可。
- 若连续出现收帧超时、CRC/ECC 增量、异常温升或无法恢复，停止该档试验并退回已验证模式。上限使用具体模组/SoC 的额定要求，不猜统一温度阈值。

每阶段记录已证实内容、证据路径、未决依赖和下一项可执行工作。较低帧率通过属于阶段成果，不能将 360fps 目标标记为完成。
